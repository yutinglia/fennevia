# Tauri installer initial implementation evidence

Dates: 2026-11-08–09 (Asia/Taipei). Direct owner request; plan 019 / ADR-095.
Source baseline: `5ad1eccf84ede8e5776ff1bcb27140079f5ce032`, plus the uncommitted
installer change on `codex/gui-installer-plan`. No release, commit, pull request,
or milestone-complete claim is made by this record.

## Implemented development scope

- Separate static Svelte/TypeScript frontend and Tauri 2 Rust host. The native
  build embeds assets and an independently generated geometric F icon.
  Only the local main window receives enumerated commands; navigation and
  new-window policy are explicit. Elevated GUI startup is rejected.
- Windows registry views and bounded Firefox INI discovery, per-entry failure
  reporting, manual native pickers, explicit selection, and revalidation.
  Saved and manually selected candidates survive rescanning. The program and
  profile are not silently paired or default-selected.
- Current-user-only path preferences with limits, optimistic revision checks,
  atomic replacement, removal, and corruption recovery. No browser files are
  changed by scan or save. Complete paths are opt-in local display only.
- Closed ownership/package schemas, source inventory/hash/artifact checks,
  installed state and missing/modified-file counts, and read-only plans for
  Install/Update/Repair/Disable/Enable/Uninstall. Preview operations show
  relative paths; no content or absolute target is serialized in the plan.
- Actual JSON fixtures generated by the existing PowerShell 5.1 and 7
  serializer. Rust accepts both encodings and whitespace forms. Repair
  preserves survivor record bytes. This is parsing evidence, not bidirectional
  install/update/remove interoperability.
- Native worker probe uses bounded stdin and correlated output. Unknown
  actions, fields, oversized payloads, and command-line paths are rejected.
  It has no transaction or elevation protocol yet.
- Frontend request gate suppresses duplicates and ignores results/errors
  after selection changes/disposal. UI text is English/Traditional Chinese.

No existing PowerShell implementation, public launcher, release packaging
inventory, or installed Firefox runtime was replaced. No real Firefox
installation/profile was installed, updated, disabled, or removed.

The npm advisory scan has two low-severity affected entries for one unpatched
deepmerge issue in the build graph; no moderate/high/critical entry in the
installer audit. The dependency record retains that finding and the still
incomplete Cargo/provenance/distribution review.

## Remaining plan gates

This is not a complete installer. P0 still needs the full safety parity table,
journal fixtures, and shared writer lock. P1 still needs pinned fixed WebView2
provenance/distribution, native UAC cancellation and same-user authenticated
handoff, and a clean offline-host trial. P2 needs real interaction/restart
acceptance. P3 still needs full release-container verification, Firefox
channel/architecture/compatibility handling, process-state checks, and handle
identity/alias protections. P4/P5/P6 (writer/rollback, complete wizard, release)
remain unimplemented.

`Preview.executable` is always false and the Tauri capability has no apply
command. No preview digest is accepted as writing consent. The selected source
package may pass its source-inventory check without having passed the separate
release-container verifier, so this development build must not be used to
authorize installation.
